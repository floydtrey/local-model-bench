# Reviewer backend connection

This separate backend lives in `native-lab/reviewer-dispatch.mjs` with an ordinary editable role prompt in `native-lab/reviewer-role.md`. It uses the same qualified native DSH/Ollama runtime path and current `qwen3.8:27b-32k-compare` setting. No Reviewer-specific model qualification exists yet. The benchmark's `session-persistence-v1/test-01/result.json` and `test-02/result.json` support separate durable Reviewer sessions, not review accuracy. Governor v7 and Worker Test 01 support the runtime/model choice for those other roles only. Treat the Reviewer assignment as provisional until a dedicated evaluation.

## Integration

Construct `ReviewerDispatcher({worker, config, root, rolePromptPath, testEvidenceRoot})` after constructing the release-bound `WorkerDispatcher`. The trusted queue controller calls `stageReview({itemId, taskIndex, testEvidence?})` only after the matching Worker task has `execution-finished`. Then call `dispatch(itemId, taskIndex, signal)` under the same serial native-run boundary. Neither call belongs in a model-facing tool or separate owner approval UI. The original intent release remains the authority; Reviewer cannot add workspace or tool permission.

The optional `testEvidence` list is for a trusted deterministic runner's actual captured existing-test results. Each entry is `{name, command, exitCode, stdoutPath, stderrPath}`; output files must be under the dedicated `testEvidenceRoot`, outside the Worker workspace. Worker prose about tests is carried as a claim and never counted as an independent test run. With no captured test result, the packet says so. The backend snapshots test output bytes and hashes them in the review packet; it does not create tests or implement Tester behavior.

The backend rereads the released intent, unchanged plan/task span, Governor guidance, exact Worker result and workspace hashes. It provides changed paths and current text content up to 64 KiB per file, plus test captures up to 64 KiB each and a 256 KiB total packet. If changed file content is binary or too large, evidence is marked incomplete and a model PASS becomes BLOCKED. Larger change sets stop before inference. A fresh tool-free DSH session receives the evidence packet. The original Worker evidence is not overwritten.

Each Reviewer task has a distinct durable one-use claim. A duplicate, concurrent call, or restart cannot replay it. A changed release, failed Worker, altered workspace, altered Reviewer prompt, or changed staged packet blocks dispatch. Stop/failure retain run evidence. The result records `modelVerdict`, effective `verdict`, reasons, test count, and raw native turns. State `reviewed-unverified` is an advisory assessment, never independent task acceptance or repair authority. Reviewer does not run tools, change code, repair, or promote itself to the next pipeline role.

`node --test native-lab/worker-dispatch.test.mjs native-lab/reviewer-dispatch.test.mjs` passes the focused synthetic boundary cases. No real Reviewer inference has run in this corrected slice. The earlier disposable Worker runtime smoke validates the native Worker transport only. Shared queue/UI/profile files and the 3082 service were not edited or restarted here.
