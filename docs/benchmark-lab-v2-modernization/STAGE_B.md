## Windows durability evidence and limits
Isolated write/flush/os.fsync/close/os.replace/read probe passed. CPython os.fsync uses MS _commit on Windows; its rename implementation uses MoveFileExW with REPLACE_EXISTING for os.replace. This does not establish metadata survival through physical power loss. Microsoft FlushFileBuffers/MoveFileEx documentation and SQLite WAL/FULL semantics constrain claims. B will use flushed content-addressed evidence and DB authority, same-directory staged report replacement, restart reconciliation of exact hashes, and deterministic abrupt-process boundaries. No physical power-cut proof claim.
