# Stage B native producer contract for Stage C

## Scope and activation
B is an opt-in library storage extension inside the existing localbench application. Defaults, native CLI argument lists, queue settings, launch scripts and ProcessRunner are unchanged. There is no API/server/frontend/event broker, alternate runner, queue claim loop, sidecar or runtime rollout. Publication is CASE-oriented: a terminal failed/blocked/unassessed case is also published. A process exit code is never qualification.

All operational callers create the SAME `CasePublisher` with `database_v2.connect(db_path)` (default operational gate, latest complete schema, WAL/FULL/FK/recursive triggers), an app-private artifact root and native UTC clock. Never use validation_only in operational wiring. `NativeV2Publisher` and `NativeRowPublisher` only adapt native evidence/identity boundaries to that publisher.

Registration for native rows is explicit: `register(key,trial_id,source_id,case_id,assessment_binding,configuration_binding)`. It verifies relational case/config identity before a start. Configuration binding contains the exact config_id and expected native row fields; assessment binding contains exact original case/input/candidate/rubric/task identifiers and an already registered `_assessor_id`. Equality preserves JSON types. Missing fields, wrong identities, stale bytes, unavailable transport or unsupported metadata never earn committed PASS. Native sealed role planning derives these IDs from the existing writer's own pre-run records, not from friendly names.

## Raw evidence and scoring
v1 preserves its exact original per-case JSON including provider raw output and retries; v2 preserves exact sealed case/trace/evaluators and transitive identity graph, raw pack bytes and verified final tool files. Existing llama.cpp artifact refs are read from the native driver evidence root and checked against declared hashes/size. OllamaChatDriver exposes optional `capture_sink=NativeV2Publisher.capture_transport`, which receives exact request/response bytes before parsing with case/turn/full effective-config reference. Digest-only raw responses are explicitly unavailable for committed PASS. Five-role writers retain full native file-path/hash identity manifests even where different source filenames contain identical bytes.

Original assessor outcomes and scores are retained; publisher does not execute an assessor. Multiple evaluators remain distinct assessment records/artifacts. Native internal first-pass/repair or transport attempts are `native_attempt_observations` linked to one canonical execution attempt, not fabricated independent trials. Root/C must expose cases, canonical attempts, native phases, tool/model turns and checks as distinct populations. Existing T13 definitions, pending-review exclusion, configuration grouping, repair evidence and predeclared repetition policy remain unchanged.

## ProcessRunner / native CLI gap and supported extension for C
Verified source: `queue_gui.core.build_command` builds argument arrays to `tools/gui/run-queue-item.ps1`. That proxy is parameterless, forwards original args, and dispatches only roles/assistant-001/assistant-002 checked-in scripts. Campaign scripts have typed/allowlisted action/phase/runtime arguments and an existing `-PythonExe` choice. `ProcessRunner.start(item_id,command,cwd)` launches exactly one shell=False child, publishes output/finished events, retains custody until acknowledge, and never mutates persistent queue from worker threads.

Current CLI parsers and campaign scripts have NO publication-path switches; a Python object cannot be injected across that subprocess boundary. B does not claim the live ProcessRunner/CLI path is already DB-enabled. C can minimally add typed opt-in app-private DB/artifact settings to the EXISTING native CLI parsers and campaign-script forwarding, instantiate the SAME publisher inside each EXISTING native main after original validation/preparation, and pass it to the above owners. For legacy/controlled rows C must create exact planned bindings from original config/input/runtime records before dispatch; five-role and v2 sealed writers already supply automatic storage planning. Extend the existing typed command builder/settings only as required, retain shell=False argv, allowlist, lock/custody, stop/acknowledgment and queue restart authority. Existing `-PythonExe` can select an explicitly approved private patched runtime; do not repurpose public/viewer input as runtime paths or execution permission. This is future C native source wiring, not a new runner/service/controller, and is not operationally enabled by B.

## Committed read / event / recovery seam
`commit(attempt_id)` transactionally stores verified artifact references, exact assessment(s), native observations, result, review pending record, immutable projection input and `case_commit_events`. Evidence is rechecked immediately before COMMIT. DB remains authoritative; projection/export/notification errors do not erase result. `events(after=cursor)` returns ordered sequence/id/result_id only. `deliver(consumer)` runs callbacks after commit, with receipts; delivery after process death is at-least-once, requiring stable ID dedup. C may implement read-only event transport over this seam; no broker is needed.

`projection(catalog=existing_T13_catalog)` rebuilds only committed rows; `export` fsyncs staging bytes and atomically replaces a derived snapshot, refusing DB/WAL/SHM and sealed-evidence targets. `recover()` audits exact structured records/indexed and unindexed bytes, preserves committed history and surfaces unavailable/corrupt evidence. Explicit `reconcile_prepared=True` only replays an already prepared, integrity-verified publication transaction; it never executes model/tools/tests, invents assessment, starts/claims work or advances dependent tasks. Native queue recovery and Owner authorization remain authoritative. `record_review` preserves completed evidence separately with execution_permission=false.
