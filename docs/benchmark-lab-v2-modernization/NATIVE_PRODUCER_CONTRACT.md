## Canonical publication, projection, event and recovery semantics
Schema10 adds append-only case_publication_revisions, case_publication_events and case_publication_receipts INSIDE the same authoritative DB. Execution/artifacts plus the pending capture revision/event commit together. Later actual native assessment preserves existing final intent/result/history and appends an assessed revision under the SAME identities; older capture bytes/rows are immutable.

projection(catalog=existing_T13_catalog) selects the latest revision per canonical attempt, INCLUDING captures awaiting assessment. Snapshot contract is benchmark-case-publication:v2. published_attempts counts latest attempts; committed_results counts final assessed publications. Revision/event count must never be used as case/trial/attempt/check count. Pending/unavailable data remains unknown, never zero or scored. Corrupt/missing required bytes stay visible as evidence_unavailable and cannot earn late success.

events(after=cursor) reads the GLOBAL case_publication_events stream, returning ordered sequence, stable id, attempt_id, revision, stage (capture/assessed) and OPTIONAL result_id (null for capture). Original case_commit_events are final-only COMPATIBILITY HISTORY, not the current client stream. Upgrade preserves old final cursor/event IDs and consumer receipts. deliver(consumer) is after-commit, at-least-once across callback/receipt crash, with stable-ID dedup and append-only receipts. No broker or control authority is needed or granted.

export fsyncs staging bytes and atomically replaces a derived snapshot; DB remains authoritative and database/WAL/SHM/sealed-evidence targets are rejected. Export/notification failure cannot undo a published capture/result. Retry uses existing stored identities, not execution.

recover audits structured/indexed/unindexed evidence, preserves visible capture with assessment pending and final assessed history, and reports corrupt/unavailable/incomplete state honestly. Explicit reconcile_prepared=True replays only already prepared, integrity-verified final publication; it never invokes assessor/model/tools/tests, claims/resumes work or advances a dependent task. Original queue restart/Owner authorization remain authoritative. record_review retains independent review evidence with execution_permission=false.

Sixteen authored abrupt-process boundaries include rollback before capture commit and visible pending capture after commit, plus original capture/assessment/result/export boundaries. These are process/power-loss simulations, not physical power-cut or hardware-cache guarantees. Windows has no portable directory fsync here.
