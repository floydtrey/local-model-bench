## Present handoff topology (verified)

**Historical roles**: fixed Planner intents and Governor packets are evaluated as their own cases. The historical Intent04 Worker steps carry actual accepted predecessor handoffs within that Worker scenario. Historical Planner output does NOT become Governor input, and Governor output does NOT control Worker input in the all-role suite. The role loop explicitly continues to the next independent role after a stopped role. See [ollama_role_campaign.py](https://github.com/floydtrey/local-model-bench/blob/79d422ee4c037ac305fd2f15c06eadf5302d0972/src/localbench/v2/ollama_role_campaign.py#L328-L369) and [flashnext_roles.py](https://github.com/floydtrey/local-model-bench/blob/79d422ee4c037ac305fd2f15c06eadf5302d0972/src/localbench/v2/flashnext_roles.py#L539-L606).

**Assistant project Worker track**: frozen PROJECT_INTENT/CONTRACT/TASKS + assigned T0x + preceding actual Worker final prose + previous workspace => Worker => independent cumulative assessor => accepted/blocked => next task. No Planner or Governor candidate output is on that chain. See [campaign.py](https://github.com/floydtrey/local-model-bench/blob/79d422ee4c037ac305fd2f15c06eadf5302d0972/src/localbench/assistant001/campaign.py#L10-L79) and [packet.py](https://github.com/floydtrey/local-model-bench/blob/79d422ee4c037ac305fd2f15c06eadf5302d0972/src/localbench/assistant001/packet.py#L126-L139).

**Assistant project probes**: Planner / Governor / Tester / Reviewer each run as a separate advisory request against a disposable copy of a supplied project run. Governor optionally reads the operator-specified plan file and canonical local governance docs. Reviewer sees candidate final claims and separately captured assessment metadata with a current-workspace hash-matching flag. Tester may modify candidate test files only. The probe decision is NOT a permission grant or automatic upstream/downstream transition. See [campaign.py](https://github.com/floydtrey/local-model-bench/blob/79d422ee4c037ac305fd2f15c06eadf5302d0972/src/localbench/assistant001/campaign.py#L81-L174).

**Separate DSH development branch (private, distinct runtime)**: verified source contains a native release-bound Planner -> Governor -> multi-task Worker -> Tester -> bounded Repair Worker -> final Reviewer path, with saved authority receipts, exact released intent/plan references, run records and stage dispatchers. The Tester requires command evidence; a bounded repair loop follows reported failures. Its own documentation says the full unattended pipeline is not independently qualified. The installed local checkout/process and any uncommitted changes were NOT verified. The benchmark project runners do NOT call this DSH pipeline.

## Authority constraints and non-equivalences

- Canonical governance remains in the separate Governor repository. The repository contains Law, State, General Intent and Governor Intent material; the benchmark should reference and hash **read bytes at run time**, not copy private governance text into versioned public project packets.
- The historical Governor battery expressly uses a scoped **qualification simulation** concerning unfinished owner identity/protected assignments. That is not production owner approval. Any new simulation must state its assumptions and expected decisions.
- Native DSH releases and local owner/plan-approval services enforce some source/version/owner-origin boundaries, but neither an LLM Governor verdict nor a first-line approval word is deterministic proof of substantive compliance with Law. Keep separate policy enforcement and model-quality evaluation.
- V2 file-tool allowlists, Python assessors, snapshots and host-execution acknowledgement do **not** isolate arbitrary candidate Python at OS/network level. Use disposable execution environments for untrusted work; do not quietly enable production KC/HA/Observer.
- Use natural-language model handoffs; format human/assessor **records**, not model prose. Authorize approved Worker inputs from benchmark-controlled references, never by blindly parsing a candidate Governor's text.
- The private DSH development branch must be compared against the operator's actual installed DSH instance before using it as an integration qualification backend; this public audit deliberately does not republish private source or canonical governance.
